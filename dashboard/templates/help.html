사용법

실행 중인 서비스에 요청을 보내고 응답을 보고 취약점을 찾는 도구입니다(DAST). 소스 코드를 읽지 않습니다. 지금 모듈 {{ counts.modules }}개 · 프로젝트 팩 {{ counts.projects }}개.

처음 쓰는 순서 화면 대상모듈표면도구 결과요청 기록ATT&CK시나리오 알아 둘 것 사전역할로그인요청 한도어디까지 하나안전장치 만들기 범용과 팩모듈 만들기아직 없는 것

처음 쓰는 순서

크게 보면 네 단계입니다. 공격 지점을 모으고 → 패턴을 넣어 보고 → 응답으로 판정하고 → 보고서로 냅니다.

  1. 대상 등록 — 프로젝트와 역할을 고르고 주소를 넣습니다. 그다음 위쪽 대상 칸에서 고르면 모든 화면이 그 대상 기준이 됩니다.
  2. 표면 수집 — 모듈 탭에서 표면 수집 모듈을 돌려 엔드포인트·파라미터를 모읍니다.
  3. 지점 점검 — 표면 탭에서 점검할 지점을 골라 지점 점검 모듈을 돌립니다. 지점마다 취약·잠재·안전이 붙습니다.
  4. 확인과 보고 — 결과 탭에서 근거를 보고 상태를 정한 뒤, 위쪽 보고서 내려받기로 받습니다.

보안 헤더처럼 지점이 필요 없는 점검은 대상 점검 모듈이라 모듈 탭에서 바로 돌립니다. 값을 직접 넣어 가며 보는 것은 도구 탭입니다.

화면

대상

점검할 서버 하나가 대상 하나입니다. 프로젝트와 역할에 묶입니다.

프로젝트
점검 대상이 되는 서비스 한 벌. 허용 범위(어디까지 요청해도 되는지)를 갖습니다.
역할
그 서비스 안에서 이 서버가 무엇인지(사용자 웹·관리자 웹·Wazuh). 아래 역할 참고.
인증 헤더
로그인이 필요한 곳을 점검할 때 넣습니다. 아래 로그인 참고.
지우면
그 대상의 실행 기록·결과·수집 지점이 같이 지워집니다.

모듈

점검 하나가 모듈 파일 하나입니다. 폴더에 넣으면 자동으로 등록됩니다.

범용 / 전용
범용은 모든 대상에, 프로젝트 전용은 그 프로젝트 대상에만 보입니다.
수동(읽기)
응답을 읽기만 합니다.
능동
요청을 더 보냅니다. 실행 전 자체 환경 확인에 체크해야 돌아갑니다.
태그
그 모듈이 다루는 ATT&CK 전술·기법.
최근 실행
15개까지 남습니다. 실패하면 이유가, 보낸 요청이 있으면 요청 N개 보기가 붙습니다.
안 보이는 모듈
다른 프로젝트 전용이거나 다른 역할용입니다. 맨 윗줄에 몇 개가 숨었는지 나옵니다.

표면

수집 모듈이 모아 둔 공격 지점 목록입니다. 여기서 골라 지점 점검 모듈을 돌립니다.

묶음
회색 줄이 엔드포인트, 그 아래가 그 주소의 파라미터입니다.
위치
쿼리(URL 의 ? 뒤) 또는 폼 본문(POST).
발견 값
수집할 때 그 칸에 있던 값. 한 파라미터를 점검할 때 나머지 칸을 이 값으로 채워 정상 요청 모양을 유지합니다. 비밀번호·토큰처럼 보이는 이름은 값을 저장하지 않습니다.
출처
link 페이지 링크 · form 폼 입력칸 · js 스크립트 안 API 경로 · import 붙여 넣은 목록. Burp·katana 로 모은 URL 은 URL 목록 가져오기 모듈에 붙여 넣으면 됩니다.

판정 칩
누르면 그 판정에 쓴 요청·응답 원문이 열립니다.
POST 지점

지점 비우기
지점과 판정만 지웁니다. 결과 탭의 결과는 남습니다.

도구

값을 넣고 바로 결과를 보는 모듈입니다. 표의 이어서 보기를 누르면 그 행의 값으로 다시 돌립니다 — 테이블 목록 → 그 테이블의 컬럼 → 그 컬럼의 값 순으로 눌러 들어갑니다.

도구넣는 값주의
자료 다운로드 경로 조작 읽을 경로(한 줄에 하나) · 인코딩 · 올라갈 단계 여러 줄은 응답 코드만, 한 줄이면 내용까지. 파일 내용은 화면에만 남습니다
강의 목록 SQL 주입 ①주입 확인 → ②테이블 → ③컬럼 → ④값 · DB 제품 한 글자씩 묻습니다. 이름 하나에 100번쯤 — 몇 개씩 끊어 읽으세요. SELECT 만 나갑니다
서버 명령 출력 읽기 sudo --version · ss -tlnp 출력 요청을 보내지 않습니다. 비밀번호·키가 섞인 출력은 넣지 마세요
열린 포트 확인 확인할 포트 · 열려 있어도 되는 포트 적어 둔 포트에만, 한 번에 30개까지. 연결만 하고 끊습니다
칼리 도구 결과 가져오기 ffuf json · gobuster 출력 · nuclei jsonl · URL 목록 요청을 보내지 않습니다. 표면으로 옮기고 nuclei 는 결과로도
기억해 둠
한 번 읽은 값은 다시 묻지 않습니다. 같은 것을 또 돌리면 요청 0번으로 끝납니다.
인코딩
새싹에듀 자료 다운로드는 ../ 를 지운 뒤에 디코딩합니다. 그래서 한 번 더 감싼 %25%32%65… 형태가 지우기를 지나쳐 ../ 로 되살아납니다.
남는 곳
찾은 것은 결과 탭에, 보낸 요청·받은 응답은 요청 기록에.

결과

찾은 것이 모이는 곳입니다. 여기서 근거를 확인하고 상태를 정합니다.

요약 카드
조치됨·오탐을 뺀 수입니다. 누르면 그 심각도만 봅니다.
필터·검색
심각도·모듈·상태는 고르면 바로 적용됩니다. 검색칸은 지금 보이는 표 안에서만 찾습니다.
상세
행을 누르거나 Enter 를 누르면 오른쪽에 열립니다. 근거·조치를 보고 상태를 바꿉니다.
상태
미확인 → 확인됨 → 조치됨. 아니라고 판단하면 오탐.
중복
같은 모듈이 같은 위치에서 같은 걸 또 찾으면 줄이 늘지 않고 갱신됩니다. 경로가 다르면 다른 줄입니다 — 보안 헤더를 세 경로에서 돌리면 경로마다 하나씩 생깁니다.
재발
조치됨으로 바꾼 것이 다시 나오면 미확인으로 되돌아갑니다. 조치판 점검에 씁니다.

요청 기록

모듈이 보낸 요청과 받은 응답이 그대로 남습니다. 판정이 맞는지 사람이 확인하는 곳입니다.

단위
패킷이 아니라 HTTP 요청·응답 하나씩입니다(포트 확인은 TCP 로 남습니다).
원문
줄을 누르면 열립니다. 노란 표시는 점검 모듈이 넣은 표식이라, 응답에서 그 표식이 어떻게 돌아왔는지 보면 판정 이유가 바로 보입니다.
여기로 오는 길
모듈 탭의 요청 N개 보기 · 결과 상세의 보낸 요청·받은 응답 보기 · 표면의 판정 칩.
가리는 것
Cookie·Authorization 과 응답의 Set-Cookie 값은 *** 로 남깁니다. .env 처럼 비밀이 섞일 응답은 본문을 저장하지 않습니다.
보고서
Markdown·JSON 에도 결과마다 요청 원문과 응답 앞부분이 들어갑니다.

알아 둘 것

사전(wordlist)

사전은 경로나 입력값을 줄단위로 적어 둔 파일입니다. 두 곳에서 씁니다.

숨은 경로 찾기
사전의 경로를 하나씩 요청해 링크에 없는 엔드포인트를 찾습니다. 페이지를 따라가는 수집은 링크로 이어진 곳만 찾으니 둘을 같이 돌리세요.
사전으로 입력값 넣어 보기
사전의 입력을 지점마다 차례로 넣고, 그대로 돌아오는지·오류가 새는지 봅니다.
{T}
보낼 때 그 요청의 표식으로 바뀝니다. 응답에서 되돌아온 자리를 찾는 데 씁니다.
특수문자 없으면
표식만 돌아온 것은 ‘반사되는 자리’라는 뜻이라 잠재로 둡니다. 걸러져야 할 글자(< > " ‘ & 등)가 그대로 돌아와야 취약입니다.
응답이 HTML 이 아니면
JSON 같은 응답은 <> 가 살아 있어도 바로 XSS 는 아닙니다. 근거에 응답 종류를 적어 둡니다.
늘리려면
SecLists 를 받아 DASH_WORDLISTS 에 폴더를 알려 주면 고르는 칸에 같이 나타납니다 (wordlists/README.md).
요청 수
숨은 경로 찾기는 경로 하나에 요청 한 번, 입력값 넣기는 지점 수 × 사전 수입니다. ‘몇 개까지’로 끊어 돌리세요.

역할 — 서버가 여럿일 때

한 프로젝트에 사용자 웹·관리자 웹·Wazuh 가 같이 있습니다. 터널로 열면 셋 다 localhost 라 다른 것은 포트뿐이고, 하위 도메인으로 가르면 호스트 이름이 서로를 덮습니다. 그래서 대상마다 역할을 골라 두고, 역할이 허용 호스트와 포트를 함께 정합니다.

가두는 것
관리자 웹 대상으로 돌린 모듈은 localhost:8443(Wazuh)으로, 사용자 웹 대상으로 돌린 모듈은 admin.sesacedu.store 로 나가지 못합니다. 등록할 때도, 실행 중에도 막습니다.
범위 적는 법
= 를 앞에 붙이면 그 호스트만(=sesacedu.store 는 admin.sesacedu.store 를 빼고), 안 붙이면 하위 도메인까지 포함합니다. 포트를 안 적으면 포트를 안 가리고, 적으면(localhost:3000) 그 포트만 허용합니다.
모듈 쪽
모듈도 맞는 역할을 정해 둡니다. 안 맞는 대상에서는 보이지 않고 억지로 돌려도 거부합니다.
보고서
주소와 함께 역할이 찍힙니다 — localhost:3000 만 남으면 나중에 어디였는지 모릅니다.
적는 곳
프로젝트 팩의 PROJECT["roles"], 모듈의 META["roles"].

로그인한 상태로 점검

대상 탭의 인증 헤더에 Cookie: … 나 Authorization: Bearer … 를 한 줄에 하나씩 넣습니다.

붙는 곳
그 대상 주소로 가는 요청에만. 다른 주소로는 나가지 않습니다.
보관
이 PC 의 instance/ DB 에만 있고, 화면·기록에는 이름만 보입니다.
주의
테스트 계정 토큰만 넣습니다.

요청 간격 · 한도

공유 서버를 덜 괴롭히려고 속도를 묶어 뒀습니다.

간격
요청 사이 {{ config.DELAY_MS }}ms 를 쉽니다.
한도
실행 하나가 {{ "{:,}".format(config.MAX_REQUESTS) }}개를 넘으면 멈춥니다.
바꾸려면
실행 전에 환경변수 DASH_DELAY_MS · DASH_MAX_REQUESTS.
자기 점검 금지
대시보드 자신(127.0.0.1:{{ config.SELF_PORT }})은 대상이 될 수 없습니다 — 자기 폼을 점검하면 실행·삭제가 진짜로 일어납니다. 시험은 연습용 대상(python demo_target.py → 5051)으로.

어디까지 하나

웹 서비스 DAST 입니다. 거의 모든 모듈이 HTTP 로만 나갑니다. HTTP 가 아닌 통신은 통로를 따로 두고, 통로마다 범위 검사 방식이 다릅니다.

통신 방식범위 검사모듈
HTTP대상 역할의 범위 — 호스트 + 포트 보안 헤더 · 표면 수집 · SQL 주입 · 경로 조작
TCP 연결만프로젝트 호스트 목록 — 포트는 안 따짐열린 포트 확인
안 나감—서버 명령 출력 읽기
TCP 를 따로 둔 이유
포트 확인은 모르는 포트를 찾는 일이라 역할의 포트 제한을 쓸 수 없습니다. 호스트만 검사하고, 대신 적어 둔 포트에만 한 번에 30개까지 연결해 봅니다.
두 가지를 견주면
ss -tlnp 는 서버가 무엇을 듣는지, 포트 확인은 밖에서 무엇이 닿는지. 차이에서 보안 그룹이 제 일을 하는지 보입니다.
SSH 실행 없음
넣으면 범위 검사가 닿지 않는 원격 실행 도구가 됩니다. 서버 설정은 출력을 붙여 넣어 받습니다.
패킷 캡처 없음
HTTPS 라 평문이 안 보이고, 요청 기록이 같은 일을 합니다.

대시보드

기록

고장
모듈 하나가 깨져도 나머지는 뜨고, 실패도 실행 기록에 남습니다.

범용modules/어느 서비스에나 쓰는 점검. 특정 주소·경로·계정은 넣지 않음
프로젝트 팩projects/<id>/__init__.py이름 · 허용 범위 · 역할
전용 모듈projects/<id>/modules/그 서비스 구성을 아는 점검

다른 서비스를 점검하게 되면 projects/ 아래에 폴더를 하나 만들면 됩니다. 앱 코드는 고치지 않습니다.

모듈 만들기

어떤 모양으로 만들지는 단계가 정합니다.

단계 (META["stage"])run 모양본보기
표면 수집 collect run(target, params) → [Point]modules/surface_crawl.py
지점 점검 probe run(target, points, params) → [Check]modules/reflection_check.py
대상 점검 check (기본) run(target, params) → [Finding]modules/_template.py
도구 tool run(target, params) → ToolResultmodules/host_report.py

SQLi·XSS·경로 조작처럼 유형별 점검은 지점 점검(probe)으로 만들면 표면 수집 결과를 그대로 받아 씁니다. 값 넣어 보내기는 probe.send(), 반사 판정은 probe.judge_reflection() — 판정 기준(패턴)만 바꾸면 됩니다.

  1. modules/_template.py 를 복사해 범용이면 modules/, 전용이면 projects/<id>/modules/ 에 둡니다. 이름이 _ 로 시작하면 등록되지 않습니다.
  2. META 를 채우고 run() 에서 단계에 맞는 값을 돌려줍니다.
  3. 대시보드를 다시 실행하면 나타납니다. 잘못 썼으면 모듈 탭 맨 위에 이유가 뜹니다.
META = {
    "id": "xss_reflect",            # 전체에서 하나뿐이어야 한다
    "name": "XSS 반사 확인",
    "category": "입력 검증",
    "stage": "probe",               # collect / check / probe / tool
    "kind": "active",               # passive(읽기만) / active(실행 전 확인 체크)
    "roles": ["user_web"],          # 비우면 어느 역할에나 보인다
    "attack": [{"tactic": "TA0001", "technique": "T1190", "name": "..."}],
    "description": "한 줄 설명",
    "params": [{"name": "path", "label": "경로", "default": "/"}],
}
